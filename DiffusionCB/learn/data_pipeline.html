Data Pipeline

There are two separate datasets, generated by two different functions in cb_harness.py, for two different downstream purposes. This is the single most important thing to internalize before touching either notebook — they are not two views of the same data.

cb_harness.py │ ┌──────────────┴──────────────┐ │ │ sweep() sweep_for_diffusion() │ │ ▼ ▼ data/ (450 files) data_diffusion/ (10,000 files) 3 classes × discrete dials memory class only × continuous δ │ │ ▼ ▼ analyze_noise_separability.ipynb sbi_data.py → load_features() baseline_classifier.ipynb │ ▼ gaussian_net.py / conditional_diffusion.py
Anatomy of one run

What one simulated "run" is

Regardless of which sweep produced it, one run = one (noise class, parameter value, seed) combination, simulated as:

for P in [X, Y, Z]: ← 3 Paulis (outer) for m in [2,4,6,8,12,16]: ← 6 sequence lengths (middle) for l in range(30): ← 30 random twirl seqs (inner) → run_once() → one circuit → 1024 shots → one f_pml value

That's 3 × 6 × 30 = 540 rows per run, each row one measured f_pml = pauli_sign · ⟨P⟩ value, plus the raw shot counts (n_plus, n_minus) and the specific twirl sequence used. Nothing is averaged away at generation time — averaging only happens downstream, deliberately, at whichever level a given analysis needs.

run_once also computes the ideal (noiseless) pauli_sign classically, by evolving the Pauli P through the same twirl sequence on a noise-free circuit — so SPAM-free ideal sign and the real noisy shot outcome are always paired per row. No noise model is injected into these three classes — the physics comes entirely from env_coupling_gate, applied via AerSampler() with no NoiseModel. State prep and measurement are ideal. This means the current data has no SPAM error in it at all — see Decisions and Assumptions.

Dataset A

data/ — the discriminability + classifier dataset

Generator: cb_harness.sweep(classes, params, seeds, base), driven from generate_cb_data.ipynb cell 8.

Grid: all 3 classes (memory, jitter, drift) × a discrete set of dial values ([0.05, 0.10, 0.15, 0.20] for memory/jitter's δ; [0.05, 0.10, 0.15, 0.20, 0.40, 0.60, 0.80] for drift's ε — wider because drift needs a bigger angle to reach the same decay) × 30 seeds.

Result: 450 files, 243,000 rows.

Dataset B

data_diffusion/ — the diffusion regression dataset

Generator: cb_harness.sweep_for_diffusion( noise_class, n_runs, delta_range, base), driven from run_diffusiondatagen.py.

Grid: memory class only, δ drawn continuously from Uniform(0.02, 0.25) — one fresh draw per run. The draw happens before the resume-skip check, so re-running after an interruption reproduces the exact same δ sequence rather than drawing new values for already-completed runs.

Result: 10,000 files (confirmed on disk).

Filename schema: {class}_run{i:04d}_delta{value:.4f}.parquet, e.g. memory_run0000_delta0.1665.parquet.

Used by: sbi_experiments.ipynb exclusively, via sbi_data.load_features().

Why continuous, and why memory-only: the regression task needs δ to sweep smoothly across its full range so the model has something to interpolate between — a 4-point discrete grid (dataset A's) would leave huge gaps. Memory was chosen as the first class to scaffold the estimator on because it's the scientifically interesting one (non-Markovian); jitter/drift regression targets were never built.
Compression

From raw rows to model input

Both analyze_noise_separability.ipynb's feature work and sbi_data.py perform the same underlying compression, collapsing only the inner (l) loop at each (P, m) bucket:

mean_(P,m) = mean_l( f_pml ) ← what standard CB already keeps (≈ λ_P shape) var_(P,m) = Var_l( f_pml ) ← what standard CB discards — the actual signal

sbi_data.load_features() does this via df.groupby(["seed","param_value","P","m"])["f_pml"].agg(["mean","var"]), then pivots so each (P, m) pair becomes two columns (mean_X2, var_X2, … mean_Z16, var_Z16). With 3 Paulis × 6 lengths × {mean, var} that's 36 features per run — the entire input to both the Gaussian net and the diffusion model's condition c.

Target y = param_value, i.e. the true δ that generated that run — known because this is simulated data with a controlled ground truth.

Two standardization steps — don't conflate them

Feature standardization vs target standardization

1. Feature standardization (sbi_data.py, both models): X is standardized using train-set statistics only — mu, sd = X[train_idx].mean(0), X[train_idx].std(0), applied to both train and test. Happens automatically inside load_features().

2. Target (δ) standardization (diffusion only, done manually in sbi_experiments.ipynb, not inside conditional_diffusion.py): delta_mean = ytr.mean(); delta_std = ytr.std(); ytr_standardized = (ytr - delta_mean) / delta_std. Required because raw δ has std ≈ 0.066, which the diffusion noise schedule (built for unit-variance signals) drowns out by around step 25 of 100 — without this step the model can trivially ignore the condition for most of training. Samples are un-standardized back to real δ units after sampling: real_delta = samples * delta_std + delta_mean. The Gaussian net needs no equivalent step — it isn't diffusing anything, so nothing assumes unit-variance signal.
