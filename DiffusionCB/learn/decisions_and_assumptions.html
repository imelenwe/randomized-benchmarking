Decisions and Assumptions

Two kinds of content here: decisions that were deliberately made (with the reasoning), and assumptions baked into the current code that haven't been tested or relaxed yet. Also — because this explainer exists specifically because the system evolved past its original spec — a section on exactly where the plan and the built system now disagree.

Deliberate decisions

SBI framing, diffusion as a consequence not a premise

Forward (noise structure → data) is cheap to simulate, inverse (data → noise structure) is the hard problem. Diffusion was explicitly not assumed as "the method" from the start — the spec frames it as one candidate estimator chosen only after the inference target is fixed, to avoid a hammer-seeking-nail error.

Matched-marginal constraint across all three noise classes

Memory, jitter, and drift are deliberately calibrated so their λP values coincide. This is what makes the discriminability result meaningful — if the classes differed in λP, any classifier "winning" by reading the marginal would be vacuous.

Quantum S+E collision model over a classical noise model

Locked as the first noise backend (2026-07-06) because it matches the process tensor formalism directly and stays tractable at 1–2 environment qubits. A classical Ornstein–Uhlenbeck model was deliberately deferred as a later, faster/tunable alternative — not built first.

Per-sequence, per-shot data retention

The entire premise of the project is that averaging over random sequences destroys the temporal-correlation signal. All three classes retain full (P, m, l) granularity; averaging only happens downstream, deliberately, at whichever level a given analysis needs.

CB over RB as the data modality

Pauli-resolved decays give richer structure than RB's single global number, and CB's repeated identical dressed cycles are a cleaner setting for detecting cycle-to-cycle correlation than RB's heterogeneous Clifford sequences. RB is out of scope as a data source.

λP from two endpoints only, not a full curve fit

lambda_P = (F[m2]/F[m1])^(1/(m2-m1)), using only m_list[0] and m_list[-1]. A simplification — worth knowing if you ever compare this λP against a more careful RB/CB fitting routine elsewhere.

Matched-decay calibration is computed from data, never hardcoded

The 3-way comparison finds the decay band all three classes can jointly reach, targets its midpoint, then picks each class's closest dial. An earlier fixed pval=0.10 and target=0.91 were deliberately removed in favor of this derived approach, so the comparison stays valid if the dataset is regenerated with different dial ranges.

Validation-loss weight selection for both models

Both train_gaussian and train_diffusion select final weights by best validation loss, not train loss. Selecting on train loss would reward the Gaussian net shrinking σ to fit training noise — the same overconfidence failure the project is trying to demonstrate diffusion fixes, so it would have undermined the comparison to let it happen on the control model too.

δ standardization lives in the notebook, not the module

conditional_diffusion.py's docstring assumes x_0 arrives already standardized — the standardization itself is done in sbi_experiments.ipynb. Deliberate separation of concerns: the diffusion module doesn't need to know what scale its target lives on; the caller does.

Two separate datasets, not one shared one

data/ and data_diffusion/ were never meant to be interchangeable — the discriminability/classifier work needs discrete, matched-decay comparison points; the regression work needs continuous coverage across the full δ range.

env_coupling_gate kept its name even after drift reused the slot

A rename to something more generic (cycle_error_gate) was proposed and explicitly declined, to keep the original name's history legible in the code rather than optimize for abstract accuracy.

Both data directories are gitignored and regenerable

Neither data/ nor data_diffusion/ is committed — both can be rebuilt exactly from the harness given the same seeds, and committing hundreds of megabytes of parquet would bloat the repo for no benefit.

Assumptions currently baked in — not yet tested or relaxed

Fixed Hamiltonian shape

couple_with_env's J=1.7, hx=1.47, hy=-1.05 (from the PRX non-Markovian RB paper) are held fixed everywhere; only δ varies. The diffusion model has no basis in its training data to generalize to a different Hamiltonian shape.

One environment qubit (dE=2)

Minimal by design, left as a knob to grow later. Real hardware environments are presumably richer.

1-qubit system only

Every dataset generated so far uses n_sys_qubits=1. The harness's K (Pauli-subsampling) parameter is currently inert as a result — subsampling only triggers for n_sys_qubits>2, and at 1 qubit there are only 3 non-identity Paulis anyway.

No SPAM error anywhere in current data

All three noise classes run through AerSampler() with no injected NoiseModel, and state prep / measurement are ideal. The feature pipeline's non-cancellation of the SPAM prefactor AP is currently a non-issue — but is a real gap the moment real hardware data (which does have SPAM) is used.

Jitter's mid-circuit reset is measurably slower in Aer

Confirmed empirically (jitter: ~14s vs memory/drift: ~1s for the same circuit count). Mid-circuit reset is non-unitary and disables Aer's fast shot-sampling path, forcing a per-shot simulation — not a bug, an expected cost, worth knowing before scaling jitter's dataset up.

Where the spec and the built system have diverged

The spec's own Progress Tracker was last updated 2026-07-11 (commit 675cdb1). Everything below happened after that and isn't reflected in its checkboxes:

The baseline classifier (commit d896137)

Phase 1's Step 5c (cross-Pauli structure) and 5d (verdict) are marked incomplete in the tracker, but in practice the cross-Pauli/ X-channel finding fell out of the same plot as the 3-way variance comparison — no separate 5c build was needed. Step 5b's "reduce to one number" genuinely was never built though — the separation is shown qualitatively (grows vs. flat), not as a single summary statistic.

Phase 2 (define the inference target) was never formally written up

Instead of picking the smallest physically-meaningful multi-dimensional output space as the spec calls for, the project pragmatically scaffolded a simpler stand-in target — single δ, memory class only — to prove the diffusion estimator works end-to-end first. The real Phase-2 decision is still open.

Phase 3's stated gate was never literally checked

The gate is "beats the Phase-1 hand-designed baseline" (the classifier, 88.7%). The diffusion model that got built is a continuous regression on δ, evaluated only against the Gaussian-net control — not against the classifier. These solve different tasks, so no single number currently satisfies the spec's original gate condition as written.

The dataset split into two wasn't planned in the spec

It emerged pragmatically once the regression task's need for continuous δ coverage became clear, and hasn't been folded back into the spec as an explicit design decision until this doc.

Phase 4 (real hardware) is completely untouched

Everything built so far is simulated. The plan's angle #3 (explaining the real λXX=0.42 ibm_fez anomaly) and the spec's Brillant gate-implementation cross-check are both still purely aspirational.
